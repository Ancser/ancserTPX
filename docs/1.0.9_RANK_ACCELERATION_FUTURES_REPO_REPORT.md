# 1.0.9 Rank Acceleration / Futures Repo Port Report

## 1. Rank acceleration 是什麼

在 futures trading 裡，rank acceleration 有兩種意思。

1. Cross-sectional rank acceleration:
   - 有很多期貨品種，例如 ES/NQ/YM/RTY/CL/GC/ZN。
   - 先算每個品種的 factor，例如 momentum、carry、term structure、volatility-adjusted return。
   - 每個時間點把所有品種排名。
   - acceleration = 這個品種排名變好的速度。
   - 典型用法：long 排名快速上升的品種，short 排名快速下降的品種。

2. Time-series rank acceleration:
   - 只有 MNQ/NQ 單一商品時，沒有真正 cross-section。
   - 所以只能把目前 momentum 放回自己過去一段時間的分布裡排名。
   - 這是本次實作使用的方法。

公式：

```text
m_t = close_t / close_{t-L} - 1
p_t = PercentRank(m_t, m_{t-W+1:t})
a_t = p_t - p_{t-k}
```

解讀：

- `m_t` 是 L bars momentum。
- `p_t` 是 momentum 在最近 W bars 的百分位排名。
- `a_t` 是 rank acceleration。
- `a_t > 0` 代表 momentum 從普通變強。
- `a_t < 0` 代表 momentum 從普通變弱。

本質上它不是單純追漲殺跌，而是在看「趨勢狀態改變的速度」。比單純 EMA break 更數學化，但仍然不是 order flow，也不是 smart money 真實倉位。

## 2. 參考 repo / 方法

本次沒有直接 copy/paste 外部 repo code，而是移植可驗證的策略思想。

- PyTrendFollow: systematic futures trend following，README 說類似 managed futures hedge funds，約 20%/year at 25% volatility。
- Quantiacs strategy-futures-trend-following: 使用 WMA 和 ROCP 判斷 futures trend，先單資產再多資產。
- NautilusTrader: 重點不是策略，而是 backtest/live 使用同一 event-driven engine，這對我們目前 backtest/live mismatch 問題更重要。
- QuantConnect futures strategy library: futures momentum、term structure、momentum + term structure 是主流 futures factor，不是單純 5m 小區間突破。
- Statistical-Trading-Strategy-in-Futures-Markets: mean-reverting trades around moving average，用 local volatility / expected slippage 決定 band。

## 7. 它為什麼可能有效

有效的第一性原理：

1. 大部分散戶看 fixed breakout / EMA cross。
2. rank acceleration 不只看「有沒有突破」，而是看 momentum 在自身歷史分布裡是否快速變強。
3. 這比較接近「資金流開始推動」的統計影子。
4. 用 ATR TP/SL 讓風控跟 volatility 同尺度，不是固定 tick 硬套。

它捕捉的是：

- momentum compression 後的釋放
- trend state transition
- volatility-adjusted continuation
- session-specific drift

## 8. 它為什麼可能失效

失效原因：

1. MNQ 單商品沒有真正 cross-sectional rank。
2. 目前用 OHLCV，不是 MBO/L2/order flow。
3. Rank acceleration 很容易把盤整噪音當成「狀態改變」。
4. ASIA session 的好結果可能來自低波動 + 特定月份漂移。
5. total loss 接近或高於 PNL，說明 edge 還不夠厚。
6. size scaling 只是放大結果，不創造新 edge。

所以它比 raw breakout 更像 factor，但還不是 institution-level strategy。

## 9. 和 trend / sigma 的關係

Rank acceleration 比 trend breakout 更抽象：

- trend breakout: 價格突破固定 zone。
- sigma: 價格到統計標準差 ladder。
- rank acceleration: momentum percentile 的變化速度。

這三者的性質：

```text
trend = location/event
sigma = distribution/location
rank acceleration = state-change factor
```

Rank acceleration 的優點是 PF 可能更好，trade 數更少。

缺點是：

- 無法知道突破位置是不是流動性目標。
- 不知道誰在打誰。
- 沒有 L2/footprint，仍然只是價格影子。

## 10. 判決

Rank acceleration 沒有全面失敗。

但目前也沒有通過「可以 live」標準。

最合理下一步：

1. 不上 live。
2. 加到 P0 shadow replay / validation queue。
3. 用 30s 或 tick data 重測 entry precision。
4. 如果能拿到多 futures 品種，再做真正 cross-sectional futures factor ranking。
5. 若只做 MNQ，rank acceleration 只能當 filter，不應當唯一 entry model。

## 14. 實盤判決

這輪比前一輪有進步，但仍然不應直接 live。

原因：

- 最好候選樣本只有 50-56 trades。
- 多數高 PNL 變體仍靠 size 2-3 放大。
- 第三段/第二段有些候選接近 0，抗 regime shift 不夠。
- 這些策略仍然是 OHLCV 派生，不是 order book / MBO edge。

目前最合理用途：

```text
1. 加入 shadow replay queue
2. 不直接開 live
3. 等 30s / tick data 後重測 entry precision
4. 若要真正 copy QuantConnect term structure，需要先收集多合約 chain / near-far spread / expiry data
5. 若要真正 copy PyTrendFollow portfolio edge，需要多品種 futures，不是只做 MNQ
```
