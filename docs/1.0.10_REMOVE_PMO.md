# 1.0.10 — 移除獨立的 PMO EMAPMO 策略

## 為什麼

`strategy="pmo"` 與 `strategy="factor" + factor_signal_family="emapmo"` 是同一個訊號
的兩套實作。`backend/strategy/pmo.py`(467 行)是 `factor.py`(961 行)裡 emapmo 家族
的舊版孤兒。

- **12 個 preset 沒有任何一個使用 `strategy="pmo"`**
- `data/` 底下沒有任何已存設定使用它
- 它額外佔用 11 個 `pmo_*` 參數與兩個引擎裡約 25 個分派點

保留它的成本是每次改動 factor 管線都要同步兩份程式碼,而它沒有任何使用者。

## 相容性

`_normalize_strategy()` 移除 `"pmo"` 之後,任何舊設定裡的 `strategy: "pmo"` 會落到
預設值 `"factor"` —— 而 `factor_signal_family` 的別名表仍保留 `"pmo": "emapmo"`,
所以舊值會被解讀成「FACTOR + EMAPMO 家族」,也就是等價的現代路徑。**不會報錯,
也不會靜默跑成別的策略。**

`_normalize_factor_family()` 裡的 `"pmo": "emapmo"` 別名**必須保留** —— 那是族別
別名,不是策略。
