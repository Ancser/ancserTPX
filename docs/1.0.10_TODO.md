# 1.0.10 TODO — Liquid Glass 折射引擎

> 現況：`tpx-glass.js` 3,146 行 + `tpx-glass.css` 1,668 行 + `tpx-glass-skin.js` 509 行。
> 全部問題都源自同一個架構決定：**折射取樣靠 DOM clone，不是靠 GPU backdrop**。

---

## 架構速覽（先看懂這個，下面的問題才有意義）

```
 [data-stage]  ─── cloneOpticalSource() ──► stageTemplates(Map)   每個 stage 一份模板
                                                  │
                                                  │ .cloneNode(true)  ← 每個 surface 各一份
                                                  ▼
 [data-optical] ──► .optical-layer (SVG filter)
                      └─ .optical-world       ← translate3d + scale 對齊實際位置
                           └─ .optical-stage-copy   ← 整個 stage 的深拷貝
                                └─ <canvas> 由 mirror 逐幀 drawImage 補像素
```

三個代價：
1. **每個 surface 都持有一份完整 stage 深拷貝**（不是共用一份）
2. **clone 會被瀏覽器重新排版** → 任何讓 clone 與原件排版不同的因素都會造成錯位
3. **canvas 的像素不會被 clone** → 要逐幀 blit，沒 blit 到就是全黑

function sanitizeClone(root) {

## 1. 月份標題字體不一致（`#cal-month-label`）

**已定位根因**，`ancserTPX.css:1209`：

```css
.cal-nav #cal-month-label {          /* ← id 選擇器 */
    font-family: -apple-system, 'Segoe UI', ...;   /* sans-serif */
    font-size: 1.25rem; font-weight: 700;          /* 粗體 */
}
```

- **實際頁面**：粗體 sans-serif 1.25rem（當初為了可視化犧牲藝術字體）
- **鏡頭裡的 clone**：id 被剝掉 → 規則失效 → 掉回頁面預設的細體等寬藝術字

使用者要的是**細的藝術字體**。所以修法不是「讓 clone 也變粗」，而是
**把這條規則本身拿掉或改成 class**，讓兩邊都用藝術字體。

順帶：改成 class 之後 clone 會自動一致，不需要再補 `.optical-stage-copy` 規則。

## 2. 鏡頭取樣的頁面比實際寬 → 段落不換行 → 少一行 → 底下整體位移

**已定位根因，而且我先前的修法是無效的（inline style 被 `!important` 蓋掉）。**

`tpx-glass.css:157`
```css
.optical-stage-copy {
    width: 100% !important;      /* ← 這行讓下面那句永遠不生效 */
    height: 100% !important;
}
```

`tpx-glass.js:974`
```js
stageCopy.style.width = `${sourceW}px`;   // 死碼:被 !important 蓋掉
```

所以 clone 的實際版面寬 = `world` 的寬 = `Math.max(rect.width, stage.scrollWidth)`。

Research 分頁的 `.institution-table` 造成水平溢出 → `scrollWidth > clientWidth`
→ **clone 拿到更寬的容器 → 原本兩行的段落變一行 → 底下所有內容上移一行**。

### 修法（三選一，建議 B）

| | 做法 | 風險 |
|---|---|---|
| A | `stageCopy.style.setProperty("width", w, "important")` | 最小改動，但 `!important` 打架難維護 |
| **B** | **CSS 移除 `width/height: 100% !important`，改由 JS 全權設定** | 要確認沒有其他地方依賴那個 100% |
| C | `world` 也改用 `clientWidth`，水平溢出不取樣 | 寬表格右半部會沒有折射 |

**版面寬度與畫布尺寸必須分開**：`world` 要大到不裁切溢出內容，
`stageCopy` 要等於 `clientWidth` 才能重現換行。

## 3. 切換／拖曳 dock 時整頁重新取樣 → 鏡頭黑掉、PNL 曲線特別常黑

### 為什麼會黑

`tpx-glass.js:1176` 的配對是**位置式**的：

```js
const targets = [...surface.stageCopy.querySelectorAll("canvas")];
sources.forEach((src, i) => { if (targets[i]) pairs.push([src, targets[i]]); });
```

App 在 clone 之後才建立的 canvas **在 clone 裡沒有對應者** → `skippedPairs` → 那塊全黑，
直到 `rebuildStageClones()` 重新拷貝為止。

### 為什麼「要等一秒」

`armStageCloneRebuild()` 的延遲鏈（`tpx-glass.js:1327`）：

```
320ms 防抖 → 若有 spring 在跑再延 180ms → requestIdleCallback(timeout 900ms)
           → 一次只重建 1 個 stage → app stage 還在排隊就再等 800ms
```

最壞情況輕易超過 1 秒。**PNL 曲線特別常黑**，因為它是切分頁時才建立/重繪的 canvas，
剛好落在「新 canvas 已存在、clone 還沒重建」的視窗內。

### 方向

- **配對改用穩定 key**（`data-canvas-id`）取代位置索引 → 新增 canvas 不會讓既有配對錯位
- **新 canvas 出現時只補那一個 pair**，不必重建整個 stage clone
- 沒有 pair 時**畫上一幀或背景色**，不要留黑
- 重建改成**增量**：只重拷變動的子樹（MutationObserver 已經有了，見 `observeLiveStageContent`）

## 4. 視窗縮放後取樣位移錯誤（次要）

`syncOpticalSurfaces()` 用 `offsetLeft/offsetTop` + `scaleX/scaleY` 推導世界座標，
註解明說「假設 transform 是純縮放」。視窗尺寸變化時 `sourceRect` 與 `scrollWidth`
同時改變，但 stage 模板還是舊的排版。

`ResizeObserver` 目前只掛在**滑桿**上（`tpx-glass.js:2688`），**沒有掛在 stage 上**。

方向：stage 級 `ResizeObserver` → 標記 dirty → 走既有的重建路徑。優先度低
（使用者已知縮放會弄壞很多東西）。

---

## 5. 鏡頭鋸齒明顯（要抗鋸齒但不能模糊、不能吃效能）

`feDisplacementMap` 逐像素取樣位移貼圖，**位移量是整數像素**，所以邊緣天生階梯狀。

不要做的：對輸出加 `feGaussianBlur`（整體糊掉 + 多一次全表面卷積）。

可以做的（成本由低到高）：

| 手法 | 做法 | 成本 |
|---|---|---|
| **A** | 對**位移貼圖**（不是輸出）加 `stdDeviation 0.5` 的模糊 | 低 —— 貼圖比輸出小很多，且只在建立時算一次 |
| B | 濾鏡加 `filterRes` 提高解析度後縮回 | 中 |
| C | 對輸出做 1px 的 `feMorphology`/`feComposite` 邊緣柔化 | 中 |
| D | 改走 CSS `backdrop-filter`（放棄 DOM clone） | 高，等於重寫 |

**建議先試 A**：位移貼圖平滑之後，位移量的空間變化連續，階梯感會顯著下降，
而輸出本身完全不模糊。

## 優化方向（架構層，非逐案修補）

### D1. clone 一致性要「可驗證」而不是「靠補丁」

現在每發現一處 id 樣式失效就在 CSS 補一條 `.optical-stage-copy[...]`。
建議加一個 dev-mode 檢查：對 clone 與原件跑 `getComputedStyle` 差異比對
（font-family / font-weight / font-size / width / line-height），差異超標就在 console 警告。
**這能一次抓出所有第 1、2 類問題，不必等使用者用肉眼發現。**

### D2. 共用 clone

目前 N 個 surface = N 份完整 stage 深拷貝。若改成**一份 clone 多個 surface 共用**
（各自只調整 `world` 的 transform），記憶體與重建成本都除以 N。
難點：`needsParentPass` / `contentStage` 那些變體需要不同的 clone 內容。

### D3. 增量重建

`MutationObserver` 已經在監看 stage 內容（`observeLiveStageContent`），
但回呼只是把整個 stage 標記 dirty。改成記錄**變動的子樹**，重建時只替換該子樹。

### D4. 把「id 剝除」換成「id 重寫」

不要 `removeAttribute("id")`，改成 `id = "clone-" +原id`，
同時在 clone 根加 `data-clone-scope`，CSS 用 `:is(#x, [data-orig-id="x"])` 之類的雙寫。
成本是要改動既有 CSS，但能根除整類問題。

## 建議順序

1. **#1**（改一條 CSS，立即可驗證）
2. **#2**（改 CSS 的 `!important` + JS 分開設定寬度）
3. **D1**（加自動比對，避免再靠肉眼找）
4. **#3**（canvas 配對改 key + 增量補 pair）
5. **#5**（位移貼圖模糊，A 案）
6. #4 / D2 / D3 / D4（架構層，視需要）
